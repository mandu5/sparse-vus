# Bounded PR evaluation engine

The released adaptive engine loses aggregate runtime because it recomputes evicted curves, constructs ROC data for PR selection, and repeatedly crosses Python/NumPy boundaries. This follow-up tests whether a compiled PR-only engine with bounded adaptive work makes exact model selection useful. It is an implementation research hypothesis, not a new p-box theorem or established SOTA.

The engine must preserve the all-score, dynamic-label metric, return every model within 1e-10 of the exact maximum, use 3e-10 separation/pruning and a 1e-12 empirical enclosure guard, and evaluate each width at most once per model. A bounded endpoint cache switches to an exact remainder sweep before eviction; all computed scalar values are reused. Memory for retained endpoint coordinates is limited per model. PR-only sparse and independent dense exhaustive kernels are mandatory comparators.

The 42 previously selected series are development data. Freeze implementation and the protocol before measuring the remaining 308 series at widths 30/100/300. These series previously appeared in exact-evaluator experiments; they are a held-out adaptive selection workload, not wholly unseen data. Report whole-call median, geometric mean, aggregate task time, regressions, all winner sets, enclosures, and hashes. Use serial randomized paired timing on Mac and public Linux CI. Exclude JIT compilation but include preparation. No claim of detector quality, real-arithmetic machine certification, global optimality, or external acceptance follows from passing tests.

The submission track produces an official anonymous TMLR variant and accurate declaration inventory. Personal authorship contributions and conflict declarations must be factual. ## Pre-formal radix amendment

An exploratory probe of the six largest-n development series (three models,
L=30) found 18/18 whole-call wins, median 2.654x, for custom eight-pass radix
preparation and a linear interval-distance scan. This is disclosed selected
development evidence, not a holdout result. Protocol version 2 adds exact PR,
paired ROC/PR, and racing radix variants before any formal run. No pilot
timings are pooled into the new experiment.

The added hypothesis is an exact O(n+(L+1)Q) evaluator for finite float64
scores under a fixed-64-bit word-RAM model, with O(n+Q+L) auxiliary memory.
Generic radix sorting is prior art; the contribution is its composition with
support-event VUS computation and the elimination of interval searches. The
implementation performs actual counting passes: NumPy stable uint64 argsort
dispatches to timsort in the inspected versions and cannot justify this bound.
Signed zeros share a threshold; all off-support ties count toward global ranks.
The original support-histogram evaluator remains a mandatory comparator.
