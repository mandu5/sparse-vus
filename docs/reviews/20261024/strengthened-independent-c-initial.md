## Theory and novelty

1. **The coupled state is sufficient under the explicit assumptions.** Inserting a labeled point changes only its owner's weighted recall mass and fragment count. The fragment update counts active neighbors inside that same true interval; a point outside the interval cannot connect two fragments inside it on a line. Precision removes at most two old components and adds one replacement. The true-start prefix formula correctly counts a component's intersected true intervals, including a true interval already active at its left endpoint. Endpoint records are queried only where a currently inactive point borders an active component, so stale interior entries do not invalidate constant-time lookup.

2. **The finite-feature theorem is credible but narrower than a general callback theorem.** Endpoint-independent features with precomputable prefixes, cheaply computable piece boundaries/coefficients, and endpoint-local aggregation are real restrictions. Moving middle weights are handled by separate prefix queries on each side of the current midpoint. The present explicit `C_gamma(n)` term fixes the hidden-cost issue for exact evaluation of the improved cardinality power. Repeated squaring gives logarithmic arithmetic-operation cost; it does not establish a rational bit-complexity bound or constant-time exact grid updates. The paper now makes these distinctions. The generic interface and polynomial weights remain theorem-only, so their practical usefulness is untested.

3. **The sorting lower bound is correct in its stated narrow model, and is not a novelty contribution.** With all-positive labels, flat weights, cardinality one, and zero existence reward, recalls associated with input queries `t_i=s_i` encode every rank. The comparison model must distinguish `n!` permutations. This does not bound scalar maximum/AUC-only output, unordered summaries, fixed-width radix algorithms, or component-tree construction. Keep this as a standard corollary. Minor clarification: if the earlier VUS section's both-classes assumption is intended globally, pad the reduction by a fixed negative sentinel point; alternatively state explicitly that the range section allows all-positive labels. This is a repairable scope ambiguity, not a fatal proof issue.

4. **Classical component trees are a serious novelty antecedent.** The [Najman–Couprie manuscript](https://perso.esiee.fr/~najmanl/habilitation/publications.pdf) describes union-find construction; live primary-endpoint retrieval was unavailable, but its original text was indexed. The [Menotti et al. author-uploaded original](https://www.researchgate.net/publication/228747458_1D_Component_tree_in_linear_time_and_space_and_its_application_to_gray-level_image_multithresholding), Sections 3.1–3.4, gives a linear 1D scan and maintains height, surface, and volume attributes. Its stated space includes the weight-domain array. [Ranefall and Wählby](https://onlinelibrary.wiley.com/doi/full/10.1002/cyto.a.22806) already compute per-threshold precision/recall from component sizes; their positives and recall denominator are size-based, rather than fixed labeled intervals. Thus births/merges, attribute maintenance, and per-threshold precision/recall are old. The remaining candidate contribution is specifically joint label-conditioned overlap, fragmentation, and moving-weight normalization. The manuscript correctly concedes that an augmented component tree implements the same algorithmic class.

5. **The argument “same tree, different labels” is necessary but weak evidence of originality.** Any supervised statistic differs with labels. The stronger argument is the explicit sufficient-state update and its inability to be replaced by an unaugmented size/count summary. The example showing equal count/first moment but different middle-weight mass is useful. A compact worked bridge example would improve the explanation further: `y=(1,1,0,0,1,1)`, `p=(0,1,1,0,1,1)`, reciprocal cardinality and middle precision bias. Inserting the zero-label point at index 3 merges `[1,2]` and `[4,5]`. Every recall pair `(W_j,c_j)` is unchanged, but precision changes from `3/4` to `(1/2)*(4/9)=2/9`. This illustrates the coupled normalization issue; it is not itself a new result.

6. **The VUS identities also appear sound, but their performance attribution must remain restrained.** At inactive events only the global prediction count changes, so PR contributes zero and ROC accumulates the predecessor rectangle. Two active square-root ramps exceed one before clipping, justifying the two-distance identity. Complete global ties are essential. However, [Boniol et al.](https://arxiv.org/html/2502.13318), Section 4.3, already separate maximum-buffer dynamic/static regions, and [Klein's pinned source](https://raw.githubusercontent.com/tomlouisklein/fast-VUS/1bae859f/fast_vus.py) already sorts maximum-support scores and uses cumulative masses. The paper's conventional direct-ramp control actually beats its released single-model evaluator. Nearest-distance geometry is therefore a representation result without a demonstrated separate runtime win on that panel; sharing explains the residual batch improvement. The existing candid ablation discussion should survive revision.

## Consumer scope and experimental interpretation

The native contract was verified directly in [TimeEval's defaults](https://raw.githubusercontent.com/TimeEval/TimeEval/7c3622757b1a3afa9a84cbc97ce132d9e379f715/timeeval/metrics/__init__.py) and [curve implementation](https://github.com/TimeEval/TimeEval/blob/7c3622757b1a3afa9a84cbc97ce132d9e379f715/timeeval/metrics/range_metrics.py): `DefaultMetrics.RANGE_PR_AUC` uses flat bias, cardinality one, and zero recall existence reward. Its callback samples unique nonminimum thresholds, uses `>=`, orders by recall/precision, and adds synthetic endpoints. This differs from both constructor defaults and the strict observed-score F1 experiment. The predecessor-binary64 threshold mapping is valid for finite binary64 scores; preserving this native contract is the right integration boundary.

The supplied Mac interval-control audit supports an exhaustive combined whole-workflow gain against both interval and raster controls, with interval/bucket about 3.03 and raster/bucket about 2.73. At nominal default sampling, raster/bucket is 1.026 with interval [0.998,1.049]. Thus an advantage over the strongest measured default combined compiled control is unsupported. The earlier nine-metric consumer's 1.031-fold end-to-end gain is an additional application limitation, not invalidated by the new consumer. Public callbacks were censored for Stock, so its compiled agreement cannot be called complete public-reference agreement.

The 26-recording panel improves the independence and detector-fidelity argument, but only two public detectors and two MSL recordings remain narrow evidence. Its maximum selection regret is approximately 0.001412, with no case crossing the stated 0.01 practical cutoff. Consequently it supports faster identical-output queries, not a broad claim that exhaustive evaluation changes useful model choices. Twelve semantic settings on the same recordings are not twelve independent domains. Timing-order intervals describe conditional execution variability, not population generalization. These limitations are currently disclosed.

The conventional interval control closes a meaningful baseline objection: [Tatbul et al.](https://papers.neurips.cc/paper_files/paper/2018/file/8f468c873a32bb0619eaeb2050ba45d1-Paper.pdf), Section 5.5, already use closed-form range overlaps. It is useful that the control is included even though it is slower than raster in several regimes. Do not select whichever conventional denominator gives a larger gain.
