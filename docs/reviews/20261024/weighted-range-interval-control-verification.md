# Conventional weighted range interval control

24 October 2026. New files: `src/sparse_vus/weighted_range_control.py`, `src/sparse_vus/timeeval_interval_adapter.py`, and their two matching test files. The existing weighted kernel, flat kernel, and TimeEval adapter were not edited; a scoped `git diff` for those three files was empty after implementation.

The control supplies a stronger conventional comparison than recomputing every point's positional weight at every query. It implements ordered interval traversal and closed-form overlap, techniques already described by [Tatbul et al., Section 5.5](https://papers.nips.cc/paper_files/paper/2018/file/8f468c873a32bb0619eaeb2050ba45d1-Paper.pdf). It is a new same-compiler implementation of that strategy, not a claim that these techniques are new or a verbatim reproduction of Tatbul's original implementation.

Each public call validates the same numeric domain and prepares true intervals, label counts, first moments, and true-interval normalizers. Every threshold then scans all scores to discover its predicted intervals. Precision uses fixed-label prefix queries. Recall traverses the two ordered interval lists, summing analytic positional mass on each intersection. A predicted interval spanning several true intervals stays at the pointer until exhausted; every other pointer advance is permanent within the query. Hence intersection traversal costs `O(K+J)`, while prediction discovery costs `O(n)` and remains inside the measured public call. Total cost is `O(n+Hn)` time and `O(n+H)` memory. Reused buffers contain no metric state from earlier queries. There is no score or query sorting.

The same four biases, three cardinalities, independent precision/recall bias selection, and macro/all-window length-weighted precision are supported. The analytic middle-weight sum splits at the scored interval's midpoint. Arithmetic-series products are twice nonnegative subinterval masses, bounded by the canonical normalizers and the existing `n <= 2^31-1` integer restriction. Floating divisions and reductions retain the same numerical limits as the weighted kernel.

The separate TimeEval adapter reuses the frozen adapter's public configuration check and copy operation, then invokes this control. It preserves native sample selection, inclusive masks via `nextafter`, curve-array dtype, endpoints, recall/precision sorting, callback name for integration, native validation, constant-score shortcut, and no-positive error. Its supported consumer remains flat/one/zero-existence only.

PYTHONPATH=src .cache/strengthening-env/bin/python -m pytest -q tests/test_weighted_range_control.py tests/test_timeeval_interval_adapter.py

Result: **151 passed in 3.90s**. Expectations use the existing independent finite-set `Fraction` oracle, literal edge cases, and the installed pinned native TimeEval implementation. The tests do not use production closed forms to generate oracle values. Coverage includes tied and unordered queries, all canonical choices, mixed biases, both aggregations, spanning/fragmented intersections, midpoint cases, large integer coordinates without large allocations, invalid inputs, and native consumer conventions. No benchmark was run, and the full project suite was not rerun under the parent's focused-test instruction. These are correctness results, not speed evidence.

The proposed full-trajectory lower-bound corollary is valid in the stated comparison model. With distinct arbitrary real scores, all-one labels, flat weights, cardinality one, existence weight zero, and input-associated queries `t_i=s_i`, exact recall is `#{j:s_j>s_i}/n`. The outputs reveal all ranks; distinguishing the `n!` rank permutations needs `log2(n!) = Omega(n log n)` comparisons. This matches the constant-feature upper bound when `H=n`. It is the standard sorting reduction, not a new lower-bound technique. It does not apply to anonymous recall multisets, maximum-only output, already supplied sorted order, unrestricted algebraic computation, or fixed-width radix algorithms.
