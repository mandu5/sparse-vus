# Strengthening the exact VUS evaluation study

This design was prepared before computing any new MSAD VUS values or model-ranking outcomes. Its goal is to test whether affordable exact evaluation changes scientific conclusions on a substantially broader, published detector pool. It does not assert that a previous laboratory has never studied approximation error.

## Audited data routes

The existing ICLR 2026 score release, [DOI 10.48804/MCVI4N](https://doi.org/10.48804/MCVI4N), publishes 29 archive configurations. The three cached archives each contain the same 350 TSB-AD evaluation series; their unused-series count is zero. Remote ZIP metadata confirmed the same series names for additional inspected configurations. Some archives put `scores/` under a model-name prefix; a downloader that checks only a root-level `scores/` directory incorrectly reports zero scores. Additional MOMENT/Chronos/TimeMoE/TimesFM configurations broaden models but do not establish an unseen-series evaluation. The cache contains 870 TSB-AD-U raw series, leaving 520 previously unmeasured raw series, 35,418,926 compressed bytes, 151,725,708 uncompressed bytes; all 19 remaining family names overlap the previous 23-family corpus. Those inputs require new detector inference because the cached score archives cover only the 350 evaluation series.

The pinned mTSBench metadata has 348 test-file entries. Excluding the prior 12 leaves 336 files totaling 2,838,553,193 source bytes. Most source families overlap previous studies; creditcard and cicids were excluded previously by a length limit and must not be described as new semantic time-series domains merely because they are new files. The [TMLR 2026 mTSBench release](https://plan-lab.github.io/projects/mtsbench/) claims a 24-detector study but the inspected primary repository/data tree did not expose an original full timestamp-score bank. Fresh classical scores are weaker evidence than a published detector panel for the present question.

The chosen route is the [MSAD VLDB 2023 published archive](https://github.com/boniolp/MSAD/tree/8141b94eb3d2b1811f81ffcf7bc8aa5dcbd6c204). Metadata-only inspection found 1,895 raw series with complete twelve-configuration stored scores; excluding training filenames and raw files above 12 MB leaves 1,863 eligible files in sixteen source families. Its full ZIP is 841,275,484 bytes, supports exact HTTP Range responses, and has a 3,584,956-byte central-directory-plus-end suffix. A metadata-stratified 128-case candidate panel initially totals 96,402,984 compressed raw-and-score payload bytes. The fixed selection, provenance, no-repair rules, and conservative checks against all previously measured observations/labels are specified in `docs/msad_score_corpus_design_20261023.md`. This avoids expensive neural inference while adding twelve actual published detector configurations. Family and possible transformed/cropped source overlaps remain explicit.

## Fixed benchmark questions and matched controls

First establish the metric contract. The existing exact method and standard published 250-threshold method must use the same global ties, width endpoints, existence reward, clipping, and averaging definition. If official implementations use different range semantics, use a separately named and independently validated exact implementation for each semantic contract; do not attribute semantic differences to threshold sampling. Freeze the upstream source commit and API parameters. Default 250 must be the baseline's actual published default, verified from its implementation.

On the frozen selected files, evaluate all twelve score vectors at prespecified widths 30, 100, and 300, plus an explicitly independent application-derived width if it is determined from observations without labels or metric results. The primary table is the default width 30; the others are sensitivity analyses. The default threshold count 250 is primary. A fixed resolution grid 32, 64, 128, 250, 500, 1000, and exact gives an accuracy/runtime frontier without tuning a resolution to individual test results. Include both the original upstream implementation and the strongest matched compiled implementation at the same resolution; compiled sampled and exact methods must compute the same PR-only or ROC-plus-PR outputs. Do not compare one method's precomputed preprocessing against another method's full call without an explicit separate amortized study.

Per case retain complete metric vectors, all tied best-model sets with frozen tolerance 1e-10, unique-winner changes, top-3 set changes, Kendall tau-b (including ties), all-pair rank reversals with exact margin greater than 1e-10, exact regret of the sampled winner, and absolute integral error. Report fraction of cases with regret at least 0.01 as a practical threshold, not only any tiny reversal. For sampled ties report both best-case and worst-case exact regret; deterministic lexical tie-breaking may be a secondary explicitly stated result. A twelve-model bank has 66 pairs, but those pairs and widths are correlated: confidence intervals and significance tests must cluster by independent parent series or source family. Do not treat all pairwise comparisons as independent trials.

Report pooled, equal-family, and per-family summaries, and show which conclusions survive the conservative duplicate filter. For parent recordings with multiple channels, add a parent-group sensitivity analysis; hash disjointness alone is insufficient evidence of independent recordings. Distinguish benchmark evaluation with available labels from deployable label-free model selection. This experiment concerns the fidelity of an offline evaluation or selector-training target, not access to labels at deployment.

A complete twelve-model evaluation must include validation, sorting, threshold construction, all widths, returned values, and winner selection. Warm each method on non-study inputs, restrict threads to one, randomize and balance method order over repeated complete passes, and record all failures and timeouts. At least five complete paired repetitions are preferable; avoid confidence intervals based on only three repeated runs. Add a separate load/decode/evaluate/rank/write collection pass. Use a timeout fixed before results and report censored cases without silently dropping slow methods. Instrument actual event counts/support/tie fragmentation, and report regressions instead of promoting only sparse cases.

## Quality gates and interpretation

The claim may be promoted only after the new semantic exact evaluator matches independent exhaustive small cases, high-precision or direct dense calculations, and the upstream full-threshold limit on all validation cases. A score direction, alignment, tie, clipping, or endpoint disagreement blocks the sampling-impact claim. Corpus acquisition success is not a numerical result. New inputs must be frozen before metric outcomes; every exclusion must follow declared validity/identity rules.

A meaningful new empirical result needs both an accuracy consequence and a competitive cost: report the distribution, not a predetermined demanded effect. If default250 ranking errors are small or exact regret is negligible, preserve that negative finding. The stronger alternatives are (1) a rigorous semantic portability result and exact evaluation across established VUS definitions; (2) structural bounds and a dispatcher that captures actual multiple-interval/tied-score workloads without regressions; or (3) end-to-end many-model evaluator scaling and exact selector-training labels. Do not manufacture a headline by replacing the corpus or adding an outcome-selected width. A theory-supported counterexample can establish possibility, but cannot establish prevalence in real releases.

## Runtime planning

The prior measured 308-series/924-score exact collection pass at width30 takes about 3.2 seconds, so 1,536 score vectors are computationally plausible. That ratio is only a planning estimate: MSAD has different lengths, quantized ties, event densities, and preprocessing. Width300 may cost roughly ten times width30 for width-linear components; original Python upstream baselines may dominate elapsed time. Freeze timeouts using a separate non-study synthetic calibration, not observed selected-case outcomes. The initial MSAD raw text is about 1.08 GB uncompressed; retain compressed per-series NPZ and source members in ignored cache, processing one series at a time. No paid compute or GPU inference is required for the selected published-score workload.
